# OutOf0 Landing Page Guide

This guide is for building the **OutOf0** landing page and org homepage.

## 1. Landing goal
The landing page should:
- introduce OutOf0 clearly
- explain what the organization builds
- showcase the product portfolio
- show the open-source / builder philosophy
- drive users to GitHub and product pages

## 2. Recommended page structure
1. Top navigation
2. Hero section
3. Product portfolio grid
4. Philosophy / manifesto strip
5. Open source / featured projects strip
6. Final CTA section
7. Footer

## 3. Top navigation
### Left
- OutOf0 lockup

### Center / right
- Products
- Open Source
- About
- Blog (optional)
- Primary CTA: **View on GitHub**

## 4. Hero section
### Headline
**OutOf0**

### Subheadline
**From zero, forward.**

### Supporting copy
We're building developer tools to serve you well — local-first, MIT licensed, and none of them
asking for your data.

### CTAs
- Primary: Explore Products
- Secondary: View on GitHub

### Visual
- Large OutOf0 symbol on the left or top-left
- Keep the hero calm, minimal, and editorial
- Do not overload with multiple illustrations

## 5. Product portfolio section
Show 3 product cards:
- Kitland — developer toolkit for modern workflows
- GitView — read, visualize, and understand Git better
- AnyPick — pick accounts, providers, and routes with control

Each card should include:
- product logo or simple icon
- one-line value proposition
- Learn more link

## 6. Philosophy / manifesto section
### Title
**From zero, we go.**

### Copy direction
We believe good products start from a blank page.
We build in public, share what we learn, and make useful tools for builders.

## 7. Open source / featured projects strip
Use a compact strip or list for:
- featured repositories
- recent releases
- highlighted open-source tools
- contribution / discussions links

## 8. Final CTA section
### Headline
**Ready to move from zero to impact?**

### Supporting copy
Build, explore, contribute.

### CTAs
- View on GitHub
- Explore Products

## 9. Visual direction
- Use whitespace as a feature
- Keep sections structured and airy
- Lean on typography over decoration
- Use signal green sparingly for action and meaning
- Avoid gradients, glows, or heavy shadows

## 10. Components
### Buttons
- Primary: Ink background / white text or signal-green background / ink text
- Secondary: white background / ink border / ink text

### Cards
- Subtle border
- 16px radius max
- light gray background or white on light sections
- simple icon + title + one sentence + link

### Code / mono snippets
Use JetBrains Mono for repo names or command examples.

## 11. Footer
Include:
- OutOf0 wordmark or lockup
- short descriptor
- product links
- GitHub
- Contact / About / Privacy (if needed)

## 12. Suggested landing copy blocks
### Hero
OutOf0
From zero, forward.
We're building developer tools to serve you well — local-first, MIT licensed, and none of them
asking for your data.

### CTA strip
Ready to move from zero to impact?
Build, explore, contribute.

Note on tone: the org exists to serve the people using the tools. Lead with that, not with the
size of the catalogue. Counts are supporting detail.
